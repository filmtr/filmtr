# Filmtr: исследование перед стартом

Цель: локальная приватная база «фильмов, достойных внимания». В ней можно искать по создателям (режиссёр, сценарист, оператор, композитор, актёры), фильтровать по жанрам и оценкам и вести свои списки: «смотрел», «хочу пересмотреть», «хочу посмотреть».

> **Статус:** конвейер данных реализован, см. [README](../README.md) и [модель данных](DATA_MODEL.md). Этот документ — исходное исследование. Выводы в нём в силе, кроме двух: стек интерфейса ещё не выбран, а «Ника» исключена из списков, потому что в Wikidata почти нет её победителей.

**Коротко:** сделать это несложно. Открытых данных хватает. Основу можно собрать за вечер из бесплатных выгрузок IMDb, а постеры, русские названия и полные съёмочные группы подтянуть через бесплатный API TMDB.

## 1. Источники данных

| Источник | Что даёт | Как получить | Условия |
|---|---|---|---|
| **IMDb Non-Commercial Datasets** | Все фильмы: год, длительность, жанры, рейтинг и **число голосов**, режиссёры и сценаристы, основные участники, люди | TSV-файлы `.tsv.gz` на `datasets.imdbws.com`, обновляются ежедневно, без ключа | Только личное некоммерческое использование. Наш случай подходит |
| **TMDB API** | Постеры и фоны, русские названия и описания, **полная съёмочная группа** (оператор, монтажёр, художник), ключевые слова, коллекции, «похожие фильмы», где посмотреть | Бесплатный ключ после регистрации, REST API | Бесплатно для некоммерческого использования с указанием TMDB как источника |
| **Wikidata** | Связка ID: IMDb ↔ TMDB ↔ **Кинопоиск** ↔ Letterboxd. Награды и номинации (Канны, Венеция, Берлин, Оскар), русские названия, страны | SPARQL-эндпоинт `query.wikidata.org` или полный дамп | CC0, без ограничений |
| **TSPDT «1000 Greatest Films»** и «21st Century 1000» | Кураторский канон по 17 тыс. списков критиков, издание 2026 года | HTML-таблицы на theyshootpictures.com | Для личного использования можно |
| **Sight & Sound 2022**, Criterion Collection | Ещё кураторские списки | Парсинг страниц или готовые списки на Letterboxd | — |
| **Твой экспорт Letterboxd / IMDb / Кинопоиска** | Что ты уже смотрел и как оценил | Letterboxd: ZIP с CSV (`watched`, `ratings`, `watchlist`, `diary`). IMDb: CSV оценок | Твои данные |
| **Кинопоиск** | Рейтинг КП, русская специфика | Официального открытого API нет, есть неофициальные (kinopoisk.dev, kinopoiskapiunofficial.tech) с дневными лимитами | Серая зона, лучше как дополнение |

Источники, которые не подходят:
- **Публичного API у Letterboxd нет.** Он выдаётся по заявке, поэтому Letterboxd годится только для экспорта своих данных.
- **OMDb** — платная обёртка над IMDb, ничего нового по сравнению с IMDb и TMDB не даёт.
- **MovieLens** — данные для рекомендательных систем, тоже лишний.

### Файлы IMDb, которые нужны

| Файл | Содержимое |
|---|---|
| `title.basics.tsv.gz` | `tconst`, тип (`movie`), название, оригинальное название, год, длительность, жанры (до 3) |
| `title.ratings.tsv.gz` | средний рейтинг и число голосов |
| `title.crew.tsv.gz` | режиссёры и сценаристы (списки `nconst`) |
| `title.principals.tsv.gz` | основные участники: актёры, композитор, оператор, монтажёр, продюсер. Около 10 человек на фильм |
| `name.basics.tsv.gz` | люди: имя, годы жизни, профессии, «известен по» |
| `title.akas.tsv.gz` | локализованные названия, включая `region=RU` |

Все файлы в сжатом виде занимают порядка нескольких гигабайт, но после фильтрации остаются десятки мегабайт.

## 2. Как отобрать «достойные» фильмы

Скачивать все фильмы не нужно (в IMDb их сотни тысяч, большинство — шум). Предлагаю **объединить несколько критериев**:

1. **Популярность и качество:** `titleType = movie`, `numVotes ≥ 10–25 тыс.`, `averageRating ≥ 6.5`. Получится примерно 5–15 тыс. фильмов в зависимости от порогов. Точные числа посчитаю на реальных данных.
2. **Критический канон:** всё из TSPDT 1000, TSPDT 21st Century, Sight & Sound и Criterion, даже если голосов мало. Так в базу попадёт артхаус и старое кино.
3. **Фестивали и премии:** победители и номинанты Канн, Венеции, Берлина, Оскара и «Ники», через Wikidata.
4. **Расширение через создателей:** у режиссёров, уже попавших в базу, добавить **всю фильмографию** с более мягким порогом. Это прямо работает на фокус «по создателям».
5. **Твои фильмы:** всё, что есть в твоих экспортах, попадает в базу без условий.

Для каждого фильма стоит хранить, через какой критерий он попал (например, `канон`, `фестиваль`, `популярность`), чтобы потом по этому фильтровать.

## 3. Обложки

- **TMDB** — основной вариант. Постеры доступны на `image.tmdb.org/t/p/{размер}/{путь}` (размеры `w185`, `w342`, `w500`, `original`). Постер `w342` весит примерно 30–60 КБ, так что 15 тыс. постеров займут около 0,5–1 ГБ. Их можно один раз скачать в локальный кэш, и всё будет работать офлайн.
- **Wikimedia Commons** — по-настоящему свободные изображения, но постеров там мало: почти все защищены авторским правом. Остаются в основном старые фильмы, перешедшие в общественное достояние.
- **Fanart.tv** — красивые фоны и логотипы, бесплатный ключ. Это опция на будущее.

Для приватного локального сервиса кэширование постеров TMDB вполне допустимо. Нужно только указать TMDB как источник на странице «О программе».

## 4. Создатели — главная фишка

С этими данными можно отвечать на такие запросы:

- все фильмы режиссёра X, которые я **ещё не видел**, отсортированные по рейтингу;
- фильмы, где **режиссёр и оператор** работали вместе (например, Тарковский и Юсов);
- «мои» люди — создатели, чьи фильмы я оценил выше всего; что у них ещё есть;
- композитор Y: все фильмы с его музыкой;
- граф связей: с кем чаще всего работал этот режиссёр.

Полные группы (оператор, монтажёр, художник) лучше брать из TMDB, `/movie/{id}/credits`: в IMDb `principals` их нет у многих фильмов.

## 5. Предлагаемая схема данных

```
film(id, imdb_id, tmdb_id, kp_id, title_ru, title_orig, year, runtime,
     countries, overview_ru, poster_path, imdb_rating, imdb_votes,
     tmdb_rating, kp_rating, sources[])
person(id, imdb_id, tmdb_id, name_ru, name_orig, photo_path)
credit(film_id, person_id, role)        -- director|writer|dop|composer|editor|actor|producer
genre(id, name) + film_genre(film_id, genre_id)
award(film_id, festival, year, category, won bool)
list(id, name) + list_item(list_id, film_id)   -- канон-списки
-- личное:
my_film(film_id, status, my_rating, watched_dates[], rewatch bool, note,
        queue_position, added_at)        -- status: seen|want|rewatch|dropped
```

## 6. Технологии

Проект начинается с нуля. Код 2013 года (Django 1.5, Python 2) в репозитории — ранний эксперимент на ту же тему, переиспользовать его не нужно.

Варианты:

| Вариант | Плюсы | Минусы |
|---|---|---|
| **Python + SQLite + Django 5** | Бесплатная админка, ORM, миграции | Интерфейс придётся делать самому, например на HTMX |
| Python + SQLite + FastAPI + лёгкий фронт | Гибко, быстро | Больше ручной работы |
| **Datasette** поверх SQLite | Поиск и фильтры почти сразу, без кода | Неудобно вести очереди и личные отметки |
| Готовые self-hosted трекеры (Yamtrack, Ryot, Movary) | Готовые списки просмотра | Нет «канона» и глубокого поиска по создателям, а это главное требование |

**Рекомендация:** Django 5 + SQLite (полнотекстовый поиск FTS5 по названиям и именам) + HTMX для фильтров без перезагрузки. Запускается одной командой локально или в Docker на домашнем сервере. SQLite на 15 тыс. фильмов и около 300 тыс. записей в `credit` работает мгновенно.

## 7. План работ

1. **Загрузчик IMDb:** скачать TSV, отфильтровать по порогам, загрузить в SQLite. Это примерно один скрипт.
2. **Списки канона:** TSPDT и Sight & Sound, сопоставленные с `imdb_id`.
3. **Wikidata:** сопоставление ID (TMDB, Кинопоиск), фестивальные награды, русские названия.
4. **Обогащение через TMDB:** постеры, русские описания, полные группы. Это фоновая задача, кэшируется локально.
5. **Импорт личных данных:** Letterboxd CSV, IMDb CSV, Кинопоиск.
6. **Интерфейс:** каталог с фильтрами (жанр, годы, страна, рейтинг, источник, «не смотрел»), страница фильма, страница человека, очередь просмотра.
7. Позже: рекомендации «похожее по создателям», статистика.

Оценка: первые три шага с минимальным интерфейсом — пара выходных.

2. Нужны русские названия и описания везде или достаточно оригинальных?
3. Запускать только на ноутбуке или на домашнем сервере / NAS, с доступом с телефона?
