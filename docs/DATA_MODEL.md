# Модель данных

Схема: [`filmtr/schema.sql`](../filmtr/schema.sql). База: `data/filmtr.db` (SQLite).

## Принципы

1. **Ключи — ID IMDb.** У фильма это `tt…`, у человека — `nm…`. Это де-факто универсальный идентификатор: Wikidata, TMDB, Letterboxd и Кинопоиск сопоставляются с ним. Поэтому каталог можно пересобирать сколько угодно, а внешние ссылки на него не ломаются.
2. **Каталог пересобирается, личное хранится отдельно.** `filmtr.db` целиком строится из открытых источников. Личные списки хранятся в CSV-файлах в `my/`, ссылаются на ID IMDb и при каждой сборке загружаются в каталог.
3. **Всё кураторское — это список.** Опросы критиков, фестивальные награды, вычисленное «ядро IMDb» и личные списки лежат в одних таблицах `list` и `list_entry`. Фильм считается **достойным внимания**, если он входит хотя бы в один список (представление `catalog`). Добавить новый критерий отбора значит добавить список.
4. **Люди — главная ось.** Для каждого фильма каталога хранится съёмочная группа с ролями. У режиссёров из каталога и из рейтингов режиссёров хранится **вся фильмография** (от 100 голосов на IMDb), даже если отдельные фильмы не попали в каталог. Так страница режиссёра показывает весь его путь.
5. **Исходные данные не теряются.** Каждая запись списка хранит исходную строку источника (`raw`) и способ сопоставления (`match`). Несопоставленные записи видны и исправляются вручную.

## Сущности

```
film ─┬─< film_genre >── genre
      ├─< film_country >── country
      ├─< rating                       (imdb; позже tmdb, kinopoisk, letterboxd)
      ├─< credit >── person            (role: director, writer, cinematographer, ...)
      └─< list_entry >── list          (опросы, премии, вычисленные подборки)
person ─< list_entry                   (рейтинги режиссёров)
```

### `film`
Фильм или другое произведение (`kind`: `movie`, `tvMovie`, `short`, `tvMiniSeries`, …). Мини-сериалы и короткий метр нужны, потому что в каноне есть «Декалог», «Берлин, Александерплац» и «Андалузский пёс». Хранит оригинальное и русское название, год, длительность и ID в Wikidata, TMDB, Кинопоиске и Letterboxd.

### `person` и `credit`
`credit` связывает фильм и человека в конкретной роли. Один человек может иметь несколько ролей в одном фильме: например, режиссёр и сценарист. Роли перечислены в справочнике `role` с русскими названиями и порядком показа.

- `billing` — порядок в титрах: меньше значит заметнее. Позволяет отделить главные роли от эпизодов.
- `job` — уточнение, например `novel` (по роману) или `co-director`.
- `characters` — имена персонажей для актёров.

### `list` и `list_entry`
- `list.kind`: `poll` (опрос), `award` (премия), `computed` (вычислено), `personal` (личный).
- `list.entity`: `film` или `person`.
- `list_entry.pos` — место в рейтинге, `year` — год награды.
- `list_entry.match`: `id` (источник сам дал ID IMDb), `exact` (название, год и режиссёр совпали), `fuzzy` (похожее название у того же режиссёра), `override` (ручное исправление), `NULL` (не найдено).

### `rating`
Внешние оценки, по одной строке на фильм и источник, в шкале источника (`scale`). Своя оценка пользователя сюда не относится: она войдёт в личный слой.

### Формула ядра IMDb

```
damped = (votes * rating + 10000 * 6.5) / (votes + 10000)   -- байесовское сглаживание
score  = (damped - 5) * log10(votes)                        -- только votes >= 10000
```

Чистый рейтинг IMDb перекошен: у фильмов с небольшим числом голосов он часто накручен (региональные новинки с оценкой 9+ при 3–5 тыс. голосов). Сглаживание и порог в 10 тыс. голосов отсекают такие фильмы. Логарифм голосов даёт вес известности, не превращая отбор в список блокбастеров. Малоизвестную классику каталог получает через опросы критиков.

## Личные списки

Главный личный механизм — списки, а не оценки. Сейчас их два: **«Любимое»** (`favorites`) — самые важные фильмы, и **«Очередь»** (`watchlist`) — что хочу посмотреть или пересмотреть. Новые списки добавляются строкой в `my/lists.csv`.

**Источник истины — CSV-файлы в `my/`, они хранятся в репозитории:**

```
my/lists.csv        id, title, description
my/favorites.csv    imdb_id, title, year, tags, note, added
my/watchlist.csv    ...
```

- Порядок строк задаёт порядок списка: в очереди это и есть очередь.
- `title` и `year` нужны только для читаемости, фильм определяется по `imdb_id`.
- Теги пишутся через «; », например `пересмотреть; с детьми`. Тег уточняет запись в конкретном списке: «посмотреть с детьми» относится к записи в очереди, а не к фильму вообще.

Файлы можно править руками или командами (`filmtr add`, `remove`, `show`, см. README). Каталог отражает их как списки вида `personal`: на каждый список строка в `list`, на каждый фильм — в `list_entry` (с `note` и `added_at`), теги — в `entry_tag`. Это происходит при каждой команде и при полной пересборке. Поэтому:

- личные фильмы входят в `catalog`, даже если не прошли ни в один другой список, как «Гуляй, Вася!»;
- если фильма ещё нет в каталоге, он копируется из IMDb-зеркала вместе со съёмочной группой и данными Wikidata;
- пересборка каталога личные данные не трогает.

Пример: всё, что стоит посмотреть с детьми.

```sql
SELECT f.title, f.year, f.directors
FROM entry_tag t
JOIN list_entry e ON e.id = t.entry_id
JOIN film_card f ON f.id = e.film_id
WHERE e.list_id = 'watchlist' AND t.tag = 'с детьми'
ORDER BY e.pos;
```

Позже можно добавить журнал просмотров и подписки на людей. Их тоже стоит хранить в `my/`.
